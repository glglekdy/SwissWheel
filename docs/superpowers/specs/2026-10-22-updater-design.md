# 업데이터 설계 문서

- 작성일: 2026-10-22
- 상태: 승인됨 (대화에서 합의), 사용자 검토 대기
- 기반: `main` (e32773b). 본 설계 문서 `2026-10-20-swisswheel-design.md`의 비목표였던 "자동 업데이트"와, `2026-10-21-desktop-menu-design.md`에서 범위 밖으로 둔 업데이트 타일을 이번에 다룬다.

## 1. 목적과 범위

**목적:** 메뉴 바의 **업데이트** 타일을 누르면 GitHub Releases에서 새 버전을 확인하고, 사용자가 승낙하면 내려받아 실행 파일을 바꾸고 다시 시작한다.

**이번 범위:**
1. 태그를 올리면 릴리스를 만드는 GitHub Actions 워크플로
2. 업데이트 확인 → 확인 창 → 내려받기 → 무결성 검사 → 교체 → 재시작
3. 재시작한 새 앱의 정리(`.old` 삭제, 완료 알림)

**범위 밖:**
- 저장소 공개 전환. 공개 전에 커밋 기록의 이메일을 어떻게 할지는 따로 정한다.
- 시작할 때 자동 확인, 전자 서명, 차등 업데이트, FFmpeg 업데이트, 이전 버전으로 되돌리기, 설치 프로그램.

**성공 기준:**
1. 새 버전이 있으면 버튼 한 번과 승낙 한 번으로 새 버전이 실행되어 트레이에 떠 있다. 설정과 "Windows 시작 시 실행"은 그대로다.
2. 받는 도중이나 교체 도중 어느 단계에서 실패해도, 기존 실행 파일이 그대로 남아 다음 실행이 정상이다.
3. 받은 파일이 릴리스의 SHA-256과 다르면 절대 실행 파일 자리에 들어가지 않는다.
4. 진행 중인 변환이 업데이트 때문에 잘리지 않는다.
5. 업데이트 기능을 쓰지 않을 때 대기 메모리 목표(15MB)와 기존 동작에 영향이 없다.

## 2. 사용자 경험

### 2.1 업데이트 타일

| 상황 | 동작 |
|---|---|
| 변환 진행 중 | 바 닫고 알림 "진행 중인 변환이 끝난 뒤 다시 눌러 주세요". 확인하지 않음 |
| 이미 확인·다운로드 중 | 바 닫고 알림 "이미 업데이트를 진행하는 중입니다" |
| 그 밖 | 바 닫고 백그라운드에서 확인 시작 |

### 2.2 확인 결과

| 결과 | 동작 |
|---|---|
| 최신 릴리스 버전 ≤ 현재 버전 | 알림 "최신 버전입니다 (v0.1.0)" |
| 네트워크 오류·HTTP 오류·응답 해석 실패 | 알림 "업데이트를 확인할 수 없습니다" (원인은 로그) |
| 릴리스에 `swisswheel.exe` 또는 `swisswheel.exe.sha256`이 없음 | 알림 "업데이트 파일을 찾을 수 없습니다" |
| 실행 파일 폴더에 쓸 수 없음 (예: Program Files) | 확인 창 "v0.2.0이 있습니다. 이 위치에서는 자동으로 바꿀 수 없어 다운로드 페이지를 엽니다." [확인] → 브라우저로 릴리스 페이지(`html_url`) |
| 새 버전 있음 | 확인 창 (2.3) |

- 최신 릴리스는 GitHub의 "latest"를 쓴다. 초안과 시험판(pre-release)은 GitHub가 이미 뺀다.
- 버전은 태그 `vX.Y.Z` 또는 `X.Y.Z`. 다른 꼴(`v1.2`, `v1.2.3-beta`)은 응답 해석 실패로 본다.

### 2.3 확인 창
- Windows 기본 확인 창(`MessageBoxW`, `MB_YESNO | MB_ICONINFORMATION | MB_TOPMOST | MB_SETFOREGROUND`), 제목 "SwissWheel 업데이트".
- 본문: "v0.2.0이 있습니다 (지금 v0.1.0).\n\n<릴리스 설명 앞부분>\n\n지금 업데이트할까요?" 릴리스 설명은 최대 600자, 넘으면 "…"로 자른다.
- [아니요]는 아무 일도 하지 않는다.

### 2.4 내려받기
- 진행은 기존 진행 표시(오른쪽 아래 진행 창, 트레이 링, 툴팁)에 한 줄로 보인다: 파일 이름 "SwissWheel v0.2.0", 작업 "업데이트".
- 실패 알림:
  - 네트워크 끊김이나 타임아웃: "업데이트 파일을 받지 못했습니다"
  - SHA-256 불일치: "업데이트 파일이 손상되었습니다"
  - 받은 파일은 지운다.
- 받기가 끝났는데 그사이 새 변환이 시작됐으면 알림 "변환이 끝나면 업데이트합니다"를 띄운다. 모든 작업이 끝나면 교체한다.

### 2.5 교체와 재시작
- 사용자는 트레이 아이콘이 잠깐 사라졌다 다시 생기는 것을 본다. 새 앱이 알림 "v0.2.0으로 업데이트했습니다"를 띄운다.
- 교체 실패: 기존 파일을 되살리고 알림 "업데이트하지 못했습니다". 지금 앱은 계속 실행된다.

## 3. 구조

### 3.1 모듈

| 위치 | 책임 |
|---|---|
| `swisswheel-core/src/update.rs` (새로) | 순수 로직: `Version` 파싱·비교, 릴리스 JSON → `Release{version, notes, page_url, exe_url, sha_url}`, `.sha256` 파일 해석(64자 16진수, 뒤에 파일 이름이 붙어도 됨), 확인 창 본문 만들기, `--after-update <pid>` 인자 해석 |
| `swisswheel/src/update/http.rs` (새로) | WinHTTP로 HTTPS GET. 리다이렉트 따라감, `User-Agent: SwissWheel/<버전>`, 연결·수신 타임아웃 30초, 진행 콜백(`Content-Length` 기준), 본문 크기 상한(JSON 1MB, exe 64MB) |
| `swisswheel/src/update/mod.rs` (새로) | 업데이트 스레드: 확인 → 확인 창 → 받기 → SHA-256 검사 → 결과를 UI 스레드로 `PostMessage` |
| `swisswheel/src/update/swap.rs` (새로) | 교체·되돌리기·새 프로세스 시작, 시작 시 `.old` 정리 |
| `app.rs` | 업데이트 타일 연결, 진행 상태를 진행 표시에 합치기, 교체 메시지 처리, 시작 인자 처리 |
| `.github/workflows/release.yml` (새로) | 릴리스 만들기 (3.4) |

- 새 의존성: `serde_json`(릴리스 JSON), `sha2`(SHA-256). `windows` 기능에 `Win32_Networking_WinHttp` 추가.
- 엔드포인트 `https://api.github.com/repos/glglekdy/SwissWheel/releases/latest`는 상수로 둔다. 디버그 빌드에서만 환경 변수 `SWISSWHEEL_UPDATE_URL`로 바꿀 수 있다(저장소 공개 전 로컬 시험용). 릴리스 빌드는 이 변수를 무시한다.

### 3.2 스레드
- 확인 창은 **업데이트 스레드에서** 띄운다. UI 스레드에서 모달 창을 띄우면 그 창의 메시지 루프가 도는 동안 `with_state`가 재진입 메시지를 버려서 훅·휠 메시지를 잃는다.
- 업데이트 스레드는 한 번에 하나다. 앱 상태의 `update: Option<UpdateHandle>`가 그 표시다.
- 진행률은 `Arc<AtomicU32>`(0..=10000)로 공유한다. UI 스레드는 기존 `TIMER_PROGRESS`(500ms)에서 읽어 진행 표시에 합친다.
- 받은 내용은 메모리(최대 64MB)에 두고, 해시가 맞은 뒤에만 `.new` 파일로 쓴다. 앱이 종료되면(트레이 → 종료) 업데이트 스레드를 기다리지 않는다. 프로세스가 끝나면서 스레드도 끝나므로 종료가 늦어지지 않고, 디스크에는 아무것도 남지 않는다(쓰는 도중이었다면 다음 시작 때 3.4의 정리가 지운다).

### 3.3 교체 순서 (UI 스레드, 모든 작업이 끝난 뒤)
`exe` = `std::env::current_exe()`, 받은 파일은 같은 폴더의 `swisswheel.exe.new`. 같은 볼륨이라 이름 바꾸기가 원자적이다.

1. 남아 있는 `swisswheel.exe.old`가 있으면 지운다. 실패하면 무시하고, 2에서 덮어쓰기로 바꾼다.
2. `exe` → `swisswheel.exe.old` (`MoveFileExW`, `MOVEFILE_REPLACE_EXISTING`). 실행 중인 exe도 이름은 바꿀 수 있다.
3. `.new` → `exe`. 실패하면 `.old` → `exe`로 되돌리고 2.5의 실패 처리를 한다.
4. `CreateProcessW(exe, "--after-update <지금 pid>")`. 실패하면 `exe`를 지우고 `.old` → `exe`로 되돌린 뒤 실패 처리를 한다.
5. 지금 앱은 평소 종료 절차(작업 러너 정리, 트레이 아이콘 제거, 훅 해제)를 거쳐 끝난다.

**폴더에 쓸 수 있는지:** 확인 단계(2.2)에서 `swisswheel.exe.new`를 만들어 보고 바로 지운다.

### 3.4 새 앱의 시작
- `--after-update <pid>`가 있으면 단일 인스턴스 뮤텍스를 잡기 **전에** 그 프로세스가 끝나기를 기다린다(`OpenProcess(SYNCHRONIZE)` + `WaitForSingleObject`, 최대 15초). 그러지 않으면 아직 살아 있는 옛 앱의 뮤텍스를 보고 바로 끝나 버린다.
  - 15초가 지나도 안 끝나면 평소처럼 진행한다. 뮤텍스가 있으면 그대로 끝나고, 옛 앱이 계속 돈다.
- 인자와 상관없이, 시작할 때마다 `swisswheel.exe.old`와 `swisswheel.exe.new`가 있으면 지운다. 지우지 못하면 다음 시작 때 다시 시도한다.
- `--after-update`로 시작했으면 알림 "v<지금 버전>으로 업데이트했습니다"를 띄운다.

### 3.5 릴리스 워크플로 (`release.yml`)
- 트리거: `v*` 태그 푸시. 실행 환경 `windows-latest`. 권한 `contents: write`.
- 순서:
  1. 태그(`v` 뗀 값)와 `Cargo.toml`의 `workspace.package.version`이 같은지 확인한다. 다르면 실패한다.
  2. `cargo test --workspace`를 돌린다. CI와 같이 FFmpeg를 설치한다.
  3. `cargo build --release`로 빌드한다.
  4. `swisswheel.exe.sha256`을 만든다. 내용은 `<64자 소문자 16진수>  swisswheel.exe`다.
  5. `gh release create <태그> swisswheel.exe swisswheel.exe.sha256 --generate-notes`로 릴리스를 만든다.
- 새 버전을 내는 법은 README에 적는다: `Cargo.toml` 버전 올리기 → 커밋 → `git tag vX.Y.Z` → `git push origin vX.Y.Z`.

## 4. 오류 처리와 안전
- 모든 단계(요청 URL, HTTP 상태, 받은 크기, 해시 결과, 각 이름 바꾸기)를 로그에 남긴다.
- 해시가 맞기 전에는 `.new`가 실행 파일 자리에 가지 않는다(3.3은 해시 통과 뒤에만 실행).
- HTTPS만 쓴다. 리다이렉트도 HTTPS가 아니면 거부한다(`WINHTTP_OPTION_REDIRECT_POLICY` = `DISALLOW_HTTPS_TO_HTTP`).
- 한계: HTTPS와 SHA-256은 전송 중 손상과 변조를 막는다. GitHub 계정 자체가 탈취되면 막지 못한다. 전자 서명은 이후 과제로 둔다.
- GitHub API 비인증 한도(시간당 60회)는 손으로 누르는 버튼에는 충분하다. 403/429는 "확인할 수 없습니다"로 처리한다.

## 5. 테스트

**자동 (`cargo test`):**
- **`update.rs`**
  - 버전 비교: 0.1.0 < 0.1.1 < 0.2.0 < 0.10.0, 같은 버전, `v` 접두어.
  - 잘못된 꼴 거부: `1.2`, `1.2.3-beta`, 빈 값.
  - 릴리스 JSON 해석: 실제 GitHub 응답 모양. 자산 누락, 다른 이름 자산만 있음.
  - `.sha256` 해석: 해시만, 해시 + 파일 이름, 대문자, 잘못된 길이.
  - 확인 창 본문: 600자 자르기, 빈 설명.
  - 인자 해석: `--after-update 1234`, 숫자 아님, 인자 없음.
- **`http.rs`**: 테스트 안에서 `127.0.0.1`의 작은 HTTP 서버(std `TcpListener`)로 확인한다. 디버그·테스트 빌드에서만 `http://127.0.0.1`을 허용한다(릴리스 빌드는 HTTPS만).
  - 본문 받기와 진행 콜백.
  - 302 리다이렉트를 따라가기.
  - 404를 오류로 처리.
  - 크기 상한을 넘으면 중단.
  - 연결 끊김을 오류로 처리.
- **`swap.rs`**: 임시 폴더의 가짜 exe 파일로 확인한다.
  - 정상 교체.
  - `.new` 이름 바꾸기 실패 시 되돌리기. 대상 이름을 잠근 파일로 재현한다.
  - 프로세스 시작 실패 시 되돌리기.
  - 남은 `.old`와 `.new` 정리.
  - 쓰기 불가 폴더 판정.
- **흐름**: 가짜 서버와 임시 폴더로 끝에서 끝까지 확인한다.
  - 확인 → 받기 → 해시 통과 → `.new` 생성.
  - 해시 불일치면 `.new`가 없음.

**수동 (`docs/manual-test.md`에 추가):** 저장소 공개 전에는 디버그 빌드 + `SWISSWHEEL_UPDATE_URL`과 로컬 서버로 한다.
- 새 버전이 있을 때 교체·재시작·완료 알림, 설정과 시작 시 실행 유지.
- 최신일 때 알림.
- 인터넷을 끊었을 때 알림.
- 손상 파일일 때 알림, 기존 exe 그대로.
- 받는 중 트레이 → 종료하면 `.new`가 남지 않음.
- 변환 중 버튼을 누를 때 알림.
- Program Files에 둔 exe면 다운로드 페이지가 열림.
- 공개 후에는 실제 v0.1.1 릴리스로 한 번 확인한다.
