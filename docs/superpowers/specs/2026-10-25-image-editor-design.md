# 사진 편집기 설계 문서

- 작성일: 2026-10-25
- 상태: 승인됨 (대화에서 합의), 사용자 검토 대기
- 기반: `main` (3ca0b18). 도구 휠(`catalog.rs`), 작업 실행기(`jobs.rs`), 이미지 엔진(`engines/image.rs`), 글래스 표면(`surface.rs`, `theme.rs`), 배치 계산 방식(`menu_geometry.rs`)을 재사용한다.

## 1. 목적과 범위

**목적:** 사진 한 장을 드래그해 도구 휠의 **✎편집**에 놓으면, 화면 가운데에 떠 있는 편집 패널이 열린다. 자르기·회전·반전·흑백·정보 지우기를 미리보기로 보면서 쌓고, 되돌리고, 한 번에 저장한다. 원본은 바꾸지 않는다.

**배경:** 처음에는 회전·흑백 같은 도구를 휠 타일로 하나씩 더하려 했으나, 도구를 하나로 모은 편집기 형태로 바꾸기로 했다. 편집기는 사진과 영상 두 하위 프로젝트로 나누고, 이 문서는 첫째인 **사진 편집기**와 두 편집기가 함께 쓸 **편집 패널 틀**을 다룬다.

**범위:**
- 편집 패널(떠 있는 글래스 패널 + 뒤 화면 어둡게).
- 사진 도구: 자르기(비율 고정 포함), 회전, 좌우·상하 반전, 흑백, 정보 지우기.
- 되돌리기·다시 하기, 저장·취소.
- 정보만 지울 때의 무손실 처리(JPG·PNG·WebP).

**범위 밖:**
- 영상 편집기 — 다음 하위 프로젝트(7장).
- 확대·이동(미리보기는 항상 패널에 맞춤), 자르기 사각형의 키보드 미세 이동.
- 밝기·대비 등 색 보정, 크기 조절(휠의 축소 도구가 있다), 글자·그림 넣기.
- 여러 장 한꺼번에 편집, 움직이는 GIF 편집.
- 원본 덮어쓰기.
- 다시 저장할 때 EXIF·색 프로필 보존(지금 변환 기능과 같이 빠진다, 2.6).

## 2. 사용자 경험

### 2.1 여는 방법
- 정지 사진 **한 장**(JPG·PNG·WebP·BMP·TIFF·GIF·ICO)을 드래그해 Space → 도구 휠 맨 끝에 **✎편집** 타일이 있다.
- 여러 장, 폴더, 움직이는 GIF, 영상·오디오면 편집 타일이 없다.
- 편집 타일은 옵션 패널이 없다. 놓으면 편집 패널이 열린다.

### 2.2 패널
```
╭────────────────────────────────────────────────────╮
│ ✂자르기 ↻회전 ⇆좌우 ⇅상하 ◐흑백 ⊘정보       photo.jpg │
│ [자유][원본][1:1][4:3][3:4][16:9][9:16]   ← 자르기 중에만 │
│                                                    │
│                 [ 사진 미리보기 ]                    │
│                                                    │
│ ↶ ↷      4032×3024 → 1080×1080      Esc 취소  ↵ 저장 │
╰────────────────────────────────────────────────────╯
```
- 커서가 있는 모니터의 작업 영역 가운데에 뜬다. 크기는 사진 비율에 맞추되 작업 영역의 80%까지, 최소 720×480 DIP.
- 패널 뒤로 그 모니터 전체가 살짝 어두워진다(어둡게 하는 창). 패널 바깥을 눌러도 닫히지 않는다.
- 패널이 키보드 포커스를 가진다. 작업 표시줄 버튼은 없다.
- 미리보기는 패널 가운데 영역에 비율을 지켜 맞춘다(확대 없음).
- 하단 가운데는 원본 크기 → 결과 크기. 편집이 없으면 원본 크기만.
- 큰 사진은 불러오는 동안 미리보기 자리에 "불러오는 중"을 보이고, 도구는 눌리지 않는다.
- 패널의 색·글래스·글꼴·강조색은 메뉴와 같다. 투명 효과가 꺼져 있으면 메뉴처럼 불투명하게 그린다.

### 2.3 도구
| 도구 | 키 | 동작 |
|---|---|---|
| ✂ 자르기 | C | 자르기 모드 켜기/끄기(2.4) |
| ↻ 회전 | R / Shift+R | 시계 방향 90° / 반시계 방향 90° |
| ⇆ 좌우 | H | 좌우 반전 |
| ⇅ 상하 | V | 상하 반전 |
| ◐ 흑백 | G | 켬/끔 토글 |
| ⊘ 정보 | I | 위치·촬영 정보 지우기 켬/끔 토글(2.6) |

- 도구 버튼은 마우스로 눌러도 된다. 마우스를 올리면 강조된다. 켜진 토글은 강조색으로 채운다.
- 회전·반전·흑백·정보는 누르는 즉시 편집 기록에 하나씩 쌓인다.

### 2.4 자르기 모드
- 들어가면 자르기 사각형이 지금 사진 전체로 놓이고, 비율 칩 줄이 도구 모음 아래에 나타난다. 다른 도구 버튼은 흐려지고 눌리지 않는다.
- 사각형 바깥은 어둡게, 안쪽에는 3분할 격자, 모서리 4개·변 4개에 손잡이.
  - 손잡이를 끌면 크기가 바뀐다. 안쪽을 끌면 옮겨진다. 사진 밖으로 나가지 않는다. 최소 16×16 픽셀(원본 기준).
  - 커서는 손잡이 방향에 맞는 크기 조절 모양, 안쪽은 이동 모양.
- 비율 칩: **자유**(기본) · **원본**(지금 사진의 비율) · 1:1 · 4:3 · 3:4 · 16:9 · 9:16.
  - 고르면 사각형이 지금 중심을 지키며 그 비율로 들어갈 수 있는 가장 큰 크기로 바뀌고, 이후 드래그는 그 비율을 지킨다.
- 하단 가운데에 자를 크기(원본 픽셀)를 보인다.
- **Enter** 또는 ✂ 다시 누르기: 사각형이 사진 전체와 다르면 자르기를 기록에 쌓고 모드를 끝낸다. 같으면 아무것도 쌓지 않고 끝낸다.
- **Esc**: 자르지 않고 모드를 끝낸다.

### 2.5 되돌리기
- ↶ / **Ctrl+Z**: 마지막 편집을 되돌린다. ↷ / **Ctrl+Y**(또는 Ctrl+Shift+Z): 다시 한다. 새 편집을 하면 다시 하기 기록은 사라진다.
- 할 것이 없으면 버튼이 흐려진다. 자르기 모드 중에는 둘 다 쓸 수 없다.

### 2.6 정보 지우기 토글
- 다시 저장하면 EXIF·색 프로필이 지금 변환 기능처럼 모두 빠진다. 그래서 정보 토글은 **다른 편집이 없을 때만** 의미가 있다.
- 다른 편집(자르기·회전·반전·흑백)이 하나라도 있으면 ⊘ 버튼은 켜진 모양으로 잠기고, 마우스를 올리면 "편집하면 정보는 자동으로 빠집니다"가 하단에 뜬다.
- 정보 지우기는 JPG·PNG·WebP에서만 버튼이 있다(다른 형식은 담을 일이 거의 없다).

### 2.7 저장
- **Enter**(자르기 모드가 아닐 때) 또는 [↵ 저장]. 편집이 없으면 버튼이 흐려지고 Enter는 아무것도 하지 않는다.
- 패널을 닫고 작업 실행기로 넘긴다. 진행 카드·결과 카드는 다른 작업과 같다(결과 카드를 누르면 폴더에서 결과가 선택된다).
- 결과는 원본 옆, 같은 형식이다.
  - 픽셀 편집이 있으면 **`photo (edited).jpg`**. JPG 95, WebP 92("높게"), 나머지 형식은 무손실. 흑백은 투명도를 지킨다(투명도가 없는 형식은 기존처럼 흰 바탕).
  - 정보 토글만 켜져 있으면 **`photo (no info).jpg`**, 다시 압축하지 않는다(3.4).
- 이름이 겹치면 기존 규칙대로 번호를 붙인다.

### 2.8 취소
- **Esc**(자르기 모드가 아닐 때) 또는 [Esc 취소].
- 편집이 없으면 바로 닫는다.
- 편집이 있으면 하단에 "편집을 버릴까요? Esc를 한 번 더 누르세요"를 띄운다. 3초 안에 Esc를 다시 누르거나 [취소]를 다시 누르면 닫고, 다른 키나 클릭을 하면 문구가 사라진다.

### 2.9 다른 기능과의 관계
- 패널이 열려 있는 동안 왼쪽 Ctrl 두 번(메뉴 열기)은 무시한다. 바탕 화면 Space 메뉴는 패널이 포커스를 가지므로 뜨지 않는다.
- 패널이 열려 있는 동안 다른 곳에서 파일을 끌어 Space를 누르면 휠은 지금처럼 뜬다. 그 휠의 ✎편집에 놓으면 이미 열린 패널을 앞으로 가져오고 "편집기가 이미 열려 있습니다" 카드를 띄운다(패널은 한 번에 하나).
- 메뉴의 재시작·업데이트는 변환 중일 때처럼, 패널이 열려 있으면 "편집기를 닫은 뒤 다시 시도하세요"로 거절한다.
- 앱을 종료하면 열린 패널의 편집은 버린다.

## 3. 구조

### 3.1 core (`swisswheel-core`)
- `catalog.rs`:
  - `Tool::Edit`, 라벨 "편집", suffix `edited`.
  - `items_for`: 입력이 정확히 하나이고 정지 사진일 때 도구 목록 끝에 `Edit`. 여러 입력의 교집합 규칙과 따로 처리한다.
- 새 모듈 `editor.rs` — 편집 상태(그리기·창과 무관):
  - `Turn { Cw, Ccw }`, `Axis { Horizontal, Vertical }`.
  - `PixelRect { x, y, w, h }`(u32).
  - `EditOp { Crop(PixelRect), Rotate(Turn), Flip(Axis), Grayscale(bool), StripInfo(bool) }`. 자르기 사각형은 **그 앞까지의 편집이 적용된 이미지 좌표**다.
  - `EditSession::new(width, height, strip_available)`:
    - `push(op)`, `undo()`, `redo()`, `can_undo()`, `can_redo()`.
    - `ops() -> &[EditOp]`, `size() -> (u32, u32)`(지금 결과 크기), `grayscale()`, `strip_info()`.
    - `has_pixel_edits()`: 자르기·회전·반전, 또는 흑백이 켜진 상태.
    - `save_kind() -> Option<SaveKind>`, `SaveKind { Edited, StripOnly }`. 편집 없음은 `None`.
  - 같은 토글을 같은 값으로 두 번 쌓지 않는다.
- 새 모듈 `editor_geometry.rs` — 배치와 마우스 계산(`menu_geometry.rs`와 같은 방식, DIP와 배율):
  - `panel_layout(work_area, scale, image_size, cropping) -> EditorLayout`: 패널 크기·위치, 도구 버튼·비율 칩·하단 버튼 박스, 미리보기 영역.
  - `hit_test(layout, point) -> EditorHit`(도구, 칩, 되돌리기, 다시 하기, 취소, 저장, 미리보기, 없음).
  - `Fit`: 미리보기 영역에 이미지를 맞춘 배율·위치, `to_image(point)`, `to_view(rect)`.
  - 자르기: `CropHandle`(모서리 4, 변 4, 안쪽), `handle_at(fit, crop, point)`, `drag(crop, handle, delta, bounds, ratio) -> PixelRect`(비율 고정, 경계, 최소 16px), `fit_ratio(crop, bounds, ratio) -> PixelRect`(2.4의 칩 동작).
  - `AspectRatio { Free, Original, Fixed(u32, u32) }`, 칩 순서 상수.

### 3.2 앱 (`swisswheel`) — 새 모듈 `editor/`
- `editor/window.rs`:
  - **어둡게 하는 창:** 모니터 전체, 최상위, `WS_EX_TOOLWINDOW`, 반투명 검정(Composition), 클릭을 삼킨다(통과시키지 않는다).
  - **패널 창:** 최상위 팝업, `WS_EX_TOOLWINDOW`(작업 표시줄 버튼 없음), 열 때 `SetForegroundWindow`로 포커스를 가진다. `Surface`(글래스 1영역, 둥근 모서리)를 쓴다.
  - 키: `WM_KEYDOWN`으로 C·R·H·V·G·I, Shift+R, Ctrl+Z/Y/Shift+Z, Enter, Esc를 받는다.
  - 마우스: 누름·끌기·뗌(`SetCapture`), 마우스 올림 추적, `WM_SETCURSOR`로 커서 모양.
  - DPI: 모니터 DPI로 배율을 정하고 `WM_DPICHANGED`는 무시한다(패널은 움직이지 않는다).
- `editor/render.rs` — Direct2D:
  - 미리보기 비트맵 하나: 열 때 디코딩한 이미지를 미리보기 영역 크기(물리 픽셀)로 줄여 만든다.
  - 회전·반전: 그리기 변환 행렬. 흑백: D2D Grayscale 효과. 자르기: 앞선 자르기들은 원본 좌표로 되돌린 잘라 그리기 영역.
  - 자르기 모드: 바깥 어둡게, 3분할 격자, 손잡이, 크기 글자.
  - 도구 모음·칩·하단 줄은 `theme.rs`의 색과 글래스 루틴, `fonts.rs`의 Pretendard, 아이콘은 휠과 같은 시스템 아이콘 글꼴.
- `editor/mod.rs` — 패널 하나의 수명:
  - `Editor::open(path, owner) -> Result<Editor>`: 창을 만들고 "불러오는 중"을 그린 뒤, 백그라운드 스레드에서 `engines::image::decode`(EXIF 방향 적용)를 부른다. 결과는 창 메시지로 받아 미리보기 비트맵을 만든다.
  - 상태: `EditSession`, 자르기 모드(지금 사각형, 끄는 손잡이, 비율), 취소 확인 중 여부와 시각.
  - 앱으로 보내는 신호(창 메시지): `Saved(path, EditPlan)`, `Closed`, `Failed(message)`.
  - `EditPlan { ops: Vec<EditOp>, kind: SaveKind }`.
- `app.rs`: 연결만 한다(이미 2,300줄이 넘는다).
  - `submit`에서 `Operation::Tool(Tool::Edit)`이면 작업 대신 `Editor::open`. 이미 열려 있으면 앞으로 가져오고 카드(2.9).
  - `Saved`를 받으면 `Job { op: Tool::Edit, inputs: [path], edits: Some(plan), .. }`를 제출. `Closed`/`Failed`는 패널을 치우고, `Failed`는 실패 카드.
  - 패널이 열리고 닫힐 때 `hook::set_editor_open`.
  - 재시작·업데이트 거절 조건에 "패널 열림"을 더한다.
- `hook.rs`: `set_editor_open(bool)`, 열려 있으면 메뉴 두 번 탭을 무시한다.
- `jobs.rs`:
  - `Job.edits: Option<EditPlan>`(다른 작업은 `None`).
  - suffix: `SaveKind::Edited` → `edited`, `StripOnly` → `no info`.
  - 실행: `Tool::Edit`이면 `engines::image::apply_edits`(Edited) 또는 `engines::metadata::strip`(StripOnly).
- `engines/image.rs`:
  - `decode`를 편집기에서 쓸 수 있게 `pub(crate)`로 연다.
  - `apply_edits(input, ops, output)`: 원본 해상도로 디코딩, `ops`를 순서대로 — `crop_imm`, `rotate90`/`rotate270`, `fliph`/`flipv`, 흑백은 마지막에 `LumaA8`/`Luma8` — 적용한 뒤 기존 `encode`로 JPG 95·WebP 92(`HIGH_*_QUALITY`).
  - `supports`: `Tool::Edit`은 모든 정지 사진.

### 3.3 그리기와 실제 결과의 일치
- 미리보기는 줄인 비트맵 + 변환이고, 저장은 원본 해상도로 같은 `ops`를 다시 적용한다. 두 경로가 같은 `EditSession`/`ops`를 쓰므로 결과 크기·방향·자를 영역은 같다. 픽셀 반올림 차이(미리보기 1px 미만)는 허용한다.

### 3.4 무손실 정보 지우기 — 새 파일 `engines/metadata.rs`
`strip(input, output)`: 정보 블록만 빼고 나머지 바이트는 그대로 복사한다. 형식은 파일 내용으로 판단한다.
- **JPG:** 마커 구간을 차례로 읽는다.
  - 남김: SOI, APP0(JFIF), APP2 중 `ICC_PROFILE`, APP14(Adobe, 색 변환 정보), DQT·SOF·DHT·DRI 등 이미지에 필요한 구간, SOS부터 EOI까지의 이미지 데이터.
  - 지움: APP1(EXIF·XMP), 나머지 APP2(MPF 등), APP3–APP13, APP15, COM, EOI 뒤 꼬리 데이터(MPF 보조 이미지, 제조사 트레일러).
  - 원본 EXIF 방향이 1이 아니면 방향 태그(0x0112) 하나만 든 최소 APP1 EXIF(`Exif\0\0` + 리틀엔디언 TIFF 헤더 + 항목 1개의 IFD0)를 APP0 바로 뒤(없으면 SOI 바로 뒤)에 넣는다. 지우면 휴대폰 세로 사진이 누워 보이기 때문이다.
- **PNG:** 청크를 차례로 읽어 `tEXt`·`zTXt`·`iTXt`·`eXIf`·`tIME`을 뺀다. `iCCP` 등 나머지는 그대로.
- **WebP:** RIFF 청크에서 `EXIF`·`XMP `를 빼고, `VP8X`가 있으면 EXIF·XMP 플래그 비트를 끄고, RIFF 크기를 고친다.
- **방향 대체:** PNG·WebP에 EXIF 방향이 1이 아니면(드묾) 바이트 처리 대신 디코딩(방향 적용) 후 다시 저장한다. PNG는 무손실, WebP는 92.
- 구조를 해석할 수 없으면 `EngineError::Read`.

## 4. 오류 처리
- 패널(창·그래픽 장치)을 못 만들면 실패 카드 "편집기를 열 수 없습니다", 로그에 원인.
- 디코딩 실패면 패널을 닫고 실패 카드 "`이름`: 이미지를 읽을 수 없습니다"(기존 문구).
- 저장 중 오류는 기존 작업 실패 카드. 결과는 임시 경로에 쓰고 옮기는 기존 흐름이라 원본은 건드리지 않는다.
- JPG 한 변 65535픽셀 한도는 기존 오류 그대로.
- 그래픽 장치를 잃으면(`D2DERR_RECREATE_TARGET`) 표면과 미리보기 비트맵을 다시 만든다(메뉴와 같은 방식). 다시 만들 수 없으면 편집을 버리고 패널을 닫고 실패 카드.

## 5. 테스트

### 5.1 core 단위 테스트
- `catalog`: 정지 사진 한 장일 때만 `Edit`이 맨 끝, 여러 장·움직이는 GIF·영상·오디오에는 없음.
- `editor`:
  - 되돌리기·다시 하기, 새 편집 뒤 다시 하기 기록 삭제, 같은 값 토글 무시.
  - 결과 크기: 회전 → 자르기 → 회전 조합.
  - `has_pixel_edits`·`save_kind`: 편집 없음, 정보만, 흑백 켰다 끔, 픽셀 편집 + 정보.
- `editor_geometry`:
  - 패널 배치: 가로·세로로 긴 사진, 작은 사진(최소 크기), 100%·150%·200% 배율, 작업 영역 80% 상한.
  - 클릭 판정: 도구 버튼, 칩(자르기 중에만), 하단 버튼.
  - `Fit` 왕복 변환.
  - 자르기 드래그: 손잡이 8개 + 이동, 비율 고정(자유·원본·16:9), 경계 막기, 최소 16px, `fit_ratio`가 중심을 지키는지.

### 5.2 이미지 엔진
- `apply_edits`: 표식 픽셀을 찍은 그림으로 회전 → 자르기 결과의 크기와 표식 위치, 반전 위치, 흑백 R=G=B, PNG 투명도 유지, JPG 출력 품질 95.
- `metadata::strip`:
  - GPS·카메라 정보가 든 JPG → 결과에 EXIF·XMP가 없고, SOS~EOI 바이트가 원본과 같다. ICC 프로필은 남는다. EOI 뒤 꼬리 데이터가 없다.
  - 방향 6인 JPG → 결과에 방향 태그만 있고, 디코딩하면 원본과 같은 방향.
  - PNG의 `tEXt`·`eXIf`가 빠지고 `IDAT`가 같다. WebP의 `EXIF`가 빠지고 `VP8X` 플래그·RIFF 크기가 맞으며 디코딩된다.
  - 망가진 파일 → `Read`.

### 5.3 작업 흐름
- 편집 `Job`이 원본 옆에 `photo (edited).jpg`를, 정보만이면 `photo (no info).jpg`를 만들고, 원본은 그대로.

### 5.4 수동 확인 (`docs/manual-test.md`에 더함)
- 한 장일 때만 ✎편집 타일, 놓으면 패널이 열리고 포커스를 가짐, 뒤 화면 어두워짐, 바깥 클릭으로 안 닫힘.

- 자르기 손잡이·이동·비율 칩의 손맛, 커서 모양.

## 7. 후속: 영상 편집기 (다음 하위 프로젝트)
이 문서의 패널 틀(창, 도구 모음, 되돌리기, 저장·취소, 키 처리)을 그대로 쓰고 영상 미리보기와 타임라인을 얹는다. 휠 타일 방식으로 설계하다 바꾸면서 합의해 둔 엔진 쪽 결정을 옮겨 둔다.
- 도구 후보: 영역 자르기, 구간 자르기, 회전·반전, 배속(0.5×·1.5×·2×), 역재생, 음량 맞추기, 현재 장면 저장(썸네일, PNG).
- 다시 인코딩은 컨테이너별 기존 변환 설정(MP4·MOV·MKV는 H.264 CRF 23 + AAC, WebM은 VP9 + Opus, AVI는 mpeg4 + MP3). 회전 메타데이터만 바꾸는 방식은 쓰지 않는다(호환성).
- 회전: `transpose=1/2`, `hflip`, `vflip`. 배속: `setpts=PTS/f` + `atempo=f`(오디오 없으면 생략), 진행률은 기대 출력 길이(원본 ÷ 배속) 기준.
- 역재생: `reverse` + `areverse`는 클립 전체를 메모리에 올린다. `가로 × 세로 × 1.5 × fps × 길이`가 1 GiB를 넘거나 셋 중 하나라도 모르면 FFmpeg를 돌리지 않고 거절("역재생은 짧은 영상만 할 수 있습니다 (1080p 기준 약 10초)"). 긴 영상의 조각 역재생은 그 뒤 과제.
- 음량 맞추기: `loudnorm=I=-16:TP=-1.5:LRA=11` + `-ar 원본 샘플레이트`(loudnorm이 192 kHz로 올리기 때문). 화면은 복사. 오디오 파일에도 쓸 수 있게 할지는 그 설계에서 정한다.
- 이를 위해 `MediaInfo`에 가로·세로·fps·샘플레이트가 필요하다.
