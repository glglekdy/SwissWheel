# 바탕화면 메뉴 바와 설정 패널 설계 문서

- 작성일: 2026-10-21
- 상태: 승인됨 (대화에서 합의), 사용자 검토 대기
- 기반: `feat/media` (97d9c82). 본 설계 문서 `2026-10-20-swisswheel-design.md`의 비목표였던 "설정 GUI"를 이번에 다룬다.

## 1. 목적과 범위

**목적:** 파일을 드래그하지 않을 때도 SwissWheel에 들어갈 입구를 만든다. 바탕화면에서 Space를 누르면 화면 상단 가운데에 반투명 타일이 가로로 늘어선 메뉴 바가 뜨고, 거기서 설정을 바로 바꿀 수 있다.

**이번 범위:**
1. 바탕화면 Space → 메뉴 바 (타일 순서: 설정, 다운로드, 플러그인, 업데이트, 재시작 — 다운로드·재시작은 `2026-10-22-ffmpeg-download-restart-design.md`)
2. 설정 타일 → 바 아래 설정 패널. 값을 바꾸면 즉시 저장·적용
3. 그에 필요한 설정 저장, 실시간 적용, Windows 시작 시 실행 (Run 레지스트리)

**범위 밖 (각각 별도 설계):** 플러그인 시스템, 업데이터. 이번에는 타일만 있고 누르면 "다음 버전에서 지원 예정입니다" 알림을 띄운다.

**성공 기준:**
1. 바탕화면이 전경일 때만 Space가 메뉴 바를 연다. 다른 앱, 바탕화면 아이콘 이름 바꾸기 중, 파일 드래그 중에는 지금과 똑같이 동작한다.
2. 메뉴 바와 설정 패널은 키보드(←→↑↓ Enter Esc)와 마우스 둘 다로 조작된다.
3. 설정 패널에서 바꾼 값은 재시작 없이 반영되고, `config.toml`의 주석과 모르는 키는 보존된다.
4. 휠의 기존 동작과 대기 메모리 목표(15MB)에 영향이 없다.

## 2. 사용자 경험

### 2.1 열기

| 입력 | 조건 | 동작 |
|---|---|---|
| `open_key` (기본 Space) | 전경 창이 바탕화면, 드래그 중 아님, 이름 바꾸기 입력칸에 포커스 없음, 바 닫힘 | 커서가 있는 모니터의 작업 영역 상단 가운데에 바 표시. 선택은 **설정** 타일 |
| `open_key` | 위 조건이 아님 | 지금과 같음 (드래그 중이면 휠, 아니면 앱으로 통과) |

- 바는 150ms 동안 위에서 살짝 내려오며 페이드인한다.
- 키 반복(누르고 있기)은 무시한다. 바가 열렸다 닫혔다 깜빡이지 않는다.
- 바 창은 휠처럼 활성화되지 않는 최상위 팝업이다(`WS_EX_NOACTIVATE`). 포커스와 바탕화면의 선택 상태를 건드리지 않고, 키는 저수준 키보드 훅으로 받는다.

### 2.2 바 조작

| 입력 | 동작 |
|---|---|
| ← / → | 타일 이동. 양 끝에서 멈춤 (순환하지 않음) |
| Enter, ↓ | 선택한 타일 실행 |
| 마우스 올림 / 클릭 | 선택 이동 / 실행 |
| Esc, `open_key`, 바 바깥 클릭 | 바 닫기 |

**타일:**
| 타일 | 아이콘 | 실행 시 |
|---|---|---|
| 설정 | 톱니바퀴 | 바 아래로 설정 패널이 내려옴 (120ms 페이드). 설정 타일은 강조 유지 |
| 다운로드 | 아래 화살표 | → `2026-10-22-ffmpeg-download-restart-design.md` |
| 플러그인 | 퍼즐 조각 | 바 닫고 트레이 알림 "다음 버전에서 지원 예정입니다" |
| 업데이트 | 원형 화살표 | → `2026-10-22-updater-design.md` |
| 재시작 | 새로 고침 | → `2026-10-22-ffmpeg-download-restart-design.md` |

### 2.3 설정 패널 조작

> → `2026-10-21-settings-categories-design.md`로 대체

| 입력 | 동작 |
|---|---|
| ↑ / ↓ | 행 이동. 첫 행에서 ↑는 패널을 닫고 바로 돌아감 |
| ← / → | 값 변경. 바뀌는 즉시 저장·적용 |
| 행의 ◀ / ▶ 클릭, 마우스 휠 | ← / → 와 같음 |
| 행 클릭 | 그 행 선택 |
| Esc | 패널만 닫고 바로 돌아감 |
| `open_key`, 바·패널 바깥 클릭 | 전부 닫기 |

저장 버튼은 없다. `open_key`를 바꾸면 그 순간부터 새 키가 닫기 키다.

### 2.4 설정 항목 (위에서부터)

> → `2026-10-21-settings-categories-design.md`로 대체

| # | 라벨 | `config.toml` 키 | 값 |
|---|---|---|---|
| 1 | 휠 열기 키 | `open_key` | Space / Tab / Esc / CapsLock / \` |
| 2 | 휠 전환 키 | `cycle_key` | 위와 같음 |
| 3 | 취소 키 | `cancel_key` | 위와 같음 |
| 4 | Windows 시작 시 실행 | `start_with_windows` | 켬 / 끔 |
| 5 | JPG 품질 | `quality.jpg` | 50~100, 5 단위 |
| 6 | WebP 품질 | `quality.webp` | 50~100, 5 단위 |
| 7 | MP3 비트레이트 | `quality.mp3_kbps` | 128 / 160 / 192 / 256 / 320 kbps |
| 8 | 진행률 카드 | `progress.window` | 켬 / 끔 |
| 9 | 트레이 링 | `progress.tray_ring` | 켬 / 끔 |

- 키 세 개는 서로 겹칠 수 없다. ← / →로 고를 때 다른 두 키가 쓰는 값은 건너뛴다.
- 파일에 직접 써 둔 값이 패널의 단계 밖이면(예: `quality.jpg = 42`, `mp3_kbps = 200`) 그대로 표시하고, ← / →를 누르면 그 방향의 가장 가까운 단계로 간다(42에서 → 50, ← 그대로; 200에서 → 256, ← 192). 단계는 패널 편의를 위한 것이고 `config.rs`의 검증 범위(1~100, 32~320)는 그대로다.
- 끝값에서 더 누르면 멈춘다 (순환하지 않음).

### 2.5 자동으로 닫히는 경우
- 전경 창이 바탕화면이 아닌 창으로 바뀜 (Alt+Tab, Win 키, 다른 창 클릭 등)
- 파일 드래그가 시작됨 (휠이 우선)
- 바를 띄운 모니터 구성이나 DPI가 바뀜

### 2.6 모양
- 첨부 레퍼런스처럼 정사각 타일(아이콘 + 아래 라벨)이 가로로 늘어선다. 타일은 반투명 회색이고 선택된 타일은 밝게 강조한다.
- 배경 처리와 색은 휠의 `Palette`를 그대로 쓴다: 아크릴 유리(Windows 11, 투명 효과 켬) 또는 불투명 단색, 다크/라이트 테마를 따른다.
- 아이콘은 휠과 같은 아이콘 폰트(Segoe Fluent Icons, 없으면 Segoe MDL2 Assets) 글리프를 쓴다.
- 설정 패널은 바와 같은 폭 기준으로 바 아래 8 DIP 간격에 붙는다. 행마다 왼쪽에 라벨, 오른쪽에 `◀ 값 ▶`.

## 3. 구조

### 3.1 `swisswheel-core` (Win32 비의존, 단위 테스트)
- `drag.rs` — `DragTracker` 확장
  - `DragEvent::KeyDown`에 바탕화면 여부를 싣는다: `KeyDown { vk, desktop: bool }`.
  - 새 상태 `Menu`(열림/닫힘). `Wheel`과 동시에 열리지 않는다.
  - 드래그 중이 아니고 `desktop`이며 메뉴가 닫혀 있을 때 `open_key` → `DragCommand::OpenMenu`.
  - 메뉴가 열려 있으면 ←→↑↓ Enter Esc `open_key`를 삼키고 `DragCommand::MenuKey(MenuKey)`로 보낸다. 다른 키는 통과한다. 키 반복은 첫 입력만 명령으로 만든다(화살표는 반복 허용, `open_key`·Enter·Esc는 반복 무시).
  - 메뉴가 열려 있을 때 왼쪽 버튼 누름 → `DragCommand::MenuPointerDown { x, y }` (앱이 바·패널 바깥이면 닫음). 드래그 시작(`Button::Dragging` 전이) → 트래커가 스스로 메뉴를 닫힘으로 두고 `DragCommand::CloseMenu`.
  - 앱이 알리는 `DragEvent::MenuClosed`로 상태를 닫힘으로 되돌린다.
  - 키 떼기 삼킴은 기존 `swallowed` 규칙을 그대로 따른다.
- `menu.rs` (신규) — 메뉴 세션 상태 머신
  - 상태: 선택 타일, 설정 패널 열림 여부와 선택 행.
  - 입력: `MenuKey`, 마우스 히트(`MenuHit`), 휠 스크롤.
  - 출력: 다시 그리기 여부와 동작(`Change { item, value }`, `Notice`, `Close`).
- `settings.rs` (신규) — 설정 항목 9개
  - 항목별 라벨, `&Config`에서 현재 값 표시 문자열, `step(&Config, item, dir) -> Option<Config>` (바뀔 게 없으면 `None`).
  - 키 중복 건너뛰기, 단계 맞춤 규칙(2.4).
- `geometry.rs` 또는 신규 `bar_geometry.rs` — 바·패널 배치(DIP)와 히트 테스트. 입력은 작업 영역과 배율, 출력은 타일/행/◀▶ 사각형.

### 3.2 `swisswheel` (앱)
- `surface.rs` (신규) — `progress.rs`의 `Surface`(D3D/D2D 스왑체인 + Composition 아크릴 배경을 둥근 사각형으로 잘라 보여줌)를 꺼내 유리 영역을 여러 개 둘 수 있게 일반화한 공용 단위. 진행 카드와 메뉴 바가 같이 쓴다. 휠의 `Renderer`는 그대로 두고, `Palette`·테마 판정·아이콘 폰트는 `wheel::render`의 것을 가져다 쓴다.
- `menubar/` (신규) — `window.rs`(팝업 창, 배치, 표시/숨김, 마우스 메시지 → `MenuHit`), `render.rs`(바와 패널 그리기), `mod.rs`(`MenuView`).
- `hook.rs` — `KeyDown` 시 바탕화면 판정: `GetForegroundWindow`가 `Progman` 또는 `WorkerW`이고 그 아래 `SHELLDLL_DefView`가 있으며, `GetGUIThreadInfo`의 포커스 창이 `Edit` 클래스가 아님. 메뉴가 열려 있을 때 바·패널 바깥의 왼쪽 버튼 누름 → 앱에 닫기 알림.
- `config_file.rs` — `save(dir, &Config)` 추가. 기존 파일을 `toml_edit`으로 읽어 바뀐 키만 고쳐 쓴다(주석·순서·모르는 키 보존). 파일이 없으면 새로 만든다.
- `autostart.rs` (신규) — `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`의 `SwissWheel` 값 쓰기/지우기(현재 exe 경로, 따옴표 포함). 시작할 때 설정과 레지스트리가 다르면 설정에 맞춘다.
- `jobs.rs` — `Runner`의 `quality`를 공유 `Arc<RwLock<Quality>>`로 바꾸고 `set_quality()` 추가. 이미 돌고 있는 작업은 시작 때 값을 그대로 쓰고, 새 작업부터 새 값을 쓴다.
- `app.rs` — 메뉴 세션과 바 창을 소유한다. `Change`를 받으면: 새 `Config` 적용 → 훅 키 바인딩 교체 → `Runner::set_quality` → 진행률 표시 설정 갱신 → 자동 실행 반영 → 저장. 전경 창 변경은 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`로 받아 바를 닫는다.

### 3.3 데이터 흐름
```
키 입력 ─ keyboard_proc ─(desktop 판정)─ DragTracker ─ OpenMenu/MenuKey ─ PostMessage ─▶ app
마우스 ─ 바 창 wnd_proc ─ MenuHit ─────────────────────────────────────────────▶ app
app: MenuSession.on_input → (다시 그리기, 동작)
     동작 Change → settings::step 결과 Config → 적용 + config_file::save
     동작 Notice → tray 알림 / Close → 바 숨김 + hook::notify(MenuClosed)
```

## 4. 오류 처리
- **저장 실패:** 값은 앱에 그대로 적용한다. 해당 행에 ⚠ 표시, 트레이 알림 "설정을 저장하지 못했습니다: …" 한 번, 로그 기록. 다음 변경 때 다시 시도한다.
- **시작 시 `config.toml`이 깨져 있었음:** 기본값으로 실행하는 지금 동작 그대로. 패널 맨 위에 "설정 파일에 오류가 있어 저장하지 않습니다" 행을 보이고, 패널에서 바꾼 값은 적용만 하고 저장하지 않는다(사용자가 직접 고치던 파일을 덮지 않음).
- **Run 레지스트리 쓰기 실패:** "Windows 시작 시 실행" 값을 원래대로 되돌리고 알림.
- **바 창이나 렌더러 생성 실패:** 로그를 남기고 메뉴 기능만 끈다(트래커가 `OpenMenu`를 내지 않도록 앱이 알림). 휠은 영향 없음.
- **훅 콜백:** 바탕화면 판정은 클래스 이름 비교 몇 번으로 끝나므로 `LowLevelHooksTimeout`에 걸리지 않는다. 판정 중 실패하면 `desktop = false`로 본다(통과가 안전한 기본값).

## 5. 테스트

**자동 (`cargo test`):**
- `drag.rs`: 바탕화면 아님 → Space 통과 / 드래그 중 → 기존대로 휠 / 메뉴 열림 → 메뉴 키만 삼키고 나머지 통과 / `open_key` 반복 무시 / 키 떼기 짝 삼킴 / 메뉴 중 드래그 시작 → `CloseMenu` / 휠과 메뉴가 동시에 열리지 않음.
- `menu.rs`: 타일 끝에서 멈춤, Enter·↓로 실행, 패널 열기·닫기, 첫 행 ↑, Esc 단계별 닫기, 마우스 히트, `open_key` 변경 뒤 새 키로 닫힘.
- `settings.rs`: 각 항목 증감과 끝값, 키 중복 건너뛰기, 단계 밖 값 표시와 맞춤.
- 배치: 작업 영역 오프셋(보조 모니터 음수 좌표), 배율 100/125/150%, 히트 테스트 경계.
- `config_file::save`: 주석·모르는 키 보존, 없는 파일 생성, 바뀐 값 왕복 파싱.

**수동 (`docs/manual-test.md`에 추가):** 바탕화면 Space 열기/Esc 닫기, 메모장·탐색기 창에서 Space 정상, 아이콘 이름 바꾸기 중 Space, 드래그 중 Space가 휠을 엶, Alt+Tab으로 자동 닫힘, 멀티 모니터·DPI 125/150%, 다크/라이트·투명 효과 끔, 설정 9개 각각 재시작 없이 반영, `config.toml` 주석 보존, 시작 시 실행 켜고 재로그인.
